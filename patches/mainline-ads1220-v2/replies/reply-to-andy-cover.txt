> When adding a brand new driver, answer to the following questions:
> - Why a new driver? Can any existed one cover these chips with some refactoring?

No existing driver covers this register map. The closest in-tree
relatives are ti-ads1119 (similar command set concept, but I2C, 16-bit,
and a single configuration register) and ti-ads124s08 (SPI, but a
different register map, command set and mux layout), so extending either
would effectively embed a second driver. The ADS1220's direct siblings
(e.g. the 16-bit ADS1120) do share this register map and can be added to
this driver later through chip_info data.

I have added this justification to the v2 cover letter.
